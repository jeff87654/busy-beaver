# 0LB3LB1RZ2RA_1LD3RB1LC2RA_3RB1LB3LC2RC_0RD2RC2LB0RA (BB(4,4) champion)

Machine: **0LB3LB1RZ2RA_1LD3RB1LC2RA_3RB1LB3LC2RC_0RD2RC2LB0RA**, the BB(4,4)
champion of the Busy Beaver Challenge.

    0    1    2    3
A   0LB  3LB  1RZ  2RA
B   1LD  3RB  1LC  2RA
C   3RB  1LB  3LC  2RC
D   0RD  2RC  2LB  0RA

Halting transition: **A2 = 1RZ** (A reading a 2 writes 1, moves right, halts).
In busycoq (`verify/BB44_rules.v`) this is the only `None` entry of `tm`;
`verify/probe.v` re-parses the machine string above and checks that all sixteen
entries agree.

This file restates the mathematics; the Coq development in [verify/](verify/)
follows it and is machine-checked.

## Notation

- `X` and `Y` in a rule stand for arbitrary left/right context; `A>` = state A, head on the
  first cell of the block to the right (moving right); `<B` = state B, head on the last
  cell of the block to the left.
- Left streams in Coq are written from the head outwards, so `0^inf 3^(2m+1) 2^k A> 1^n R`
  is `Bcfg k n m r` with left stream `[2]^^k *> [3]^^(2m+1) *> const 0`.
- "X → Y" means zero or more steps (Coq's `-->*`).

The one configuration family (Ligocki):

    B(k, n, m) R  =  0^inf  3^(2m+1)  2^k  A>  1^n  R

and the run is

    0^inf A> 0^inf  -(98)->  B(2, 6, 0)  0^inf
        ->  B(2, 0, 126)  0^inf                    (Ligocki's descent, k = 1)
        ->  B(1, 254, 0)  0^inf                    (phase B)
        ->  B(1, 0, 254)  0^inf                    (Ligocki's descent, k = 0)
        ->  B(510, 1, 0)  2 1 3 0^inf              (phase D)
        ->  B(510, 0, g_509(0))  2 1 3 0^inf      (Ligocki's descent, k = 509)
        -(A2 = 1RZ, 1 step)->  0^inf  3^(2 g_509(0)+1)  2^510  1 Z> 1 3 0^inf .

The functions (Coq: `g` in `BB44_rules.v`):

    g_0(m)     =  m + 1
    g_(k+1)(m) =  g_k^(2m+2)(0)

## Why the BB(4,4) champion needs two extra phases

The BB(4,4) champion differs from the BB(3,4) one only in three entries —
A0 (`0LB` instead of `1RB`), B0 (`1LD` instead of `2LC`) — and in the extra
state D:

    BB(3,4):  A   1RB  3LB  1RZ  2RA     BB(4,4):  A   0LB  3LB  1RZ  2RA
              B   2LC  3RB  1LC  2RA               B   1LD  3RB  1LC  2RA
              C   3RB  1LB  3LC  2RC               C   3RB  1LB  3LC  2RC
                                                   D   0RD  2RC  2LB  0RA

Every transition that Ligocki's descent uses (A1, A3, B1, B2, B3, C0, C1, C2,
C3) is unchanged, so Lemma 1, Corollary 2, the turnaround and Theorem 3
(`B_rule`) port over verbatim.  What *does* change is the way the machine gets
into the descent: the BB(4,4) champion enters it only after two extra phases,
which are proved in `BB44_rules.v` as `B_phase` and `D_phase`.

### 1. Start (`BB44_start.v`, `start`)

The blank tape reaches `B(2,6,0) 0^inf` in exactly 98 steps.  Proven in Coq by
stepping (busycoq's `execute`); also cross-checked by `tools/check.py`.  The 98
steps are cut into chunks of 10 (`BB44_start.v` is generated by
`tools/gen_start.py`), because busycoq's `execute` re-normalises the whole
accumulated proof term at every step and a single 98-step `execute` is cubic
in the number of steps.

### 2. The descent rules (`BB44_rules.v`, `L1`, `Cor2`, `turnaround`, `B_rule`)

**Lemma 1**: `3 2^k <B → 2^k <B 1` (k ≥ 1, 2k+1 steps).
**Corollary 2**: `3^m 2^k <B → 2^k <B 1^m` ((2k+1)m steps).
**Theorem 3**: for k ≥ 1, n, m ≥ 0,

        B(k, n, m) R  →  B(k, 0, g_(k-1)^n(m)) R

Proof by double induction (on k, then n), using Lemma 1/Corollary 2 and the
"turnaround" step sequence

        0^inf 2^(k+1) <B 1^(2m+1) 3 1^n R  →  0^inf 3 2^k A> 1^(2m+2) 3 1^n R .

The Coq proof decomposes these into elementary sweeps (`C_sweep_left`,
`C_right_3s`, `A_3s`, `B_1s`, `BA_sweep`, `turnaround`), each proven by a
simple induction.

### 3. Phase B (`BB44_rules.v`, `B_phase`)

    B(2, 0, m) 0^inf   →   B(1, 2m+2, 0) 0^inf                       (10m+10 steps)

The head sits on the outermost 2 of the block `2^2 3^(2m+1)`.  A five-step
cycle (B2, C2, C3, C3, C1) eats one 3 of the left block and appends one 1 to
the right stream:

    2 3^(2m+1) <B 1^j   →   2 3^(2m) <B 1^(j+1) .

After `2m+1` cycles the 3-block is gone; four further steps (B2, C2, C0, B3)
leave the head in state A on a 1, in front of `1^(2m+2)`.

### 4. Phase D (`BB44_rules.v`, `D_phase`)

    B(1, 0, m) 0^inf   →   B(2m+2, 1, 0) 2 1 3 0^inf               (20m+35 steps)

Six sub-phases:

| phase | steps | what happens |
| --- | --- | --- |
| D1 | `1 + 3(2m+1)` | A0 enters the 3-block; a three-step cycle (B2, C3, C1) eats the block, one 3 at a time, each 3 replaced by a 1 on the right |
| D2 | `4 + 2m` | B2 and C0 set up a run of 1s that the B1 sweep (`B_1s`) turns into 3s |
| D3 | `5 + 3(2m+2)` | B0 enters state D; a three-step cycle (D3, A1, B0) walks left over the 3-block, one 3 at a time |
| D4 | `4 + 2m` | C sweeps right over the 3-block, writing 2s (`C_right_3s`) |
| D5 | `9 + 2m` | a detour through B, D and A, then a C sweep left over the 2-block, writing 3s (`C_sweep_left`) |
| D6 | `3 + 2m` | C0 and B3 set up a run of 3s that the A3 sweep (`A_3s`) turns into 2s |

The machine is now in `B(510, 1, 0) 2 1 3 0^inf` (for m = 254), i.e. it has
510 twos to its left, a 3 beyond them, and the tail `2 1 3` to its right.

### 5. Halting step (`BB44_run.v`)

`B(k, 0, m) 2` — A reads the 2, i.e. `c_final = Bcfg 510 0 g509 (2 1 3 0^inf)`
with `g509 = g_509(0)` — the machine halts there; the halting write turns the 2
into a 1, so the final tape is

    0^inf 3^(2 g509+1) 2^510 1 Z> 1 3 0^inf

with `sigma = 2 g509 + 514` nonzero cells.

## The score

Closed form (BB44_score.v, `g_closed`), by induction on k, using
`Nat.iter` lemmas and the coincidence `2 ↑^k 2 = 4`:

    2 * g_(k+1)(m) + 4  =  2 ↑^k (2m+4)

Corollary (`g_iter_closed`): `2 * g_k^n(0) + 4 = 2 ↑^k (n+2)`; with k = 509, n = 1:

    sigma = 2 * g_509(0) + 514 = (2 ↑^509 3) + 510 .

(`knuth n a b` in Coq is a ↑^n b with a ↑^0 b = a·b, as in Ligocki's post.)

In particular **sigma > 2 ↑^509 3**, i.e. the machine produces more than 2 with
509 Knuth up-arrows applied to 3 nonblank symbols.

The last step, `sigma_eq`, is where the two closed forms meet.  `g509` is sealed
behind a `sig` (`g509_spec`/`g509_eq`), the rule `B_rule` is instantiated
through the abstracted version `B_rule_gen` so that no conversion between
`g509` and the raw `Nat.iter 1 (g 509) 0` is ever required, and the arithmetic
is done by the generic lemma `score_generic : 2x+4 = K -> 2x+514 = K+510`.
See `verify/coq_quirks.md` for why this is necessary.
